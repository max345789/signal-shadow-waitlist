# Architecture & Design Decisions (DECISIONS.md)

This file records every sensible default chosen when building **Trust Marketplace**, along with the rationale and constraints.

---

## Phase 0: Foundation

### 1. Project Location & Tooling
- **Decision**: Scaffolded in `trust-marketplace` using Next.js (App Router), TypeScript (`strict: true`, `noUncheckedIndexedAccess: true`), Tailwind CSS `3.4.19`, Radix UI primitives, Prisma `6.x` (PostgreSQL), `ioredis`, `jose`, `otpauth`, `zod`, Vitest, and Playwright.
- **Why**: Next.js + TypeScript + Tailwind + Radix UI + Prisma + Redis matches Section 7 defaults. Using Tailwind `3.4.19` with `theme.colors` completely replacing default colors ensures non-Section-4 colors (e.g., `purple-*`, `slate-*`, `emerald-*`) cannot even be generated by Tailwind CSS.

### 2. Strict Section 4 Color System & WCAG AA Contrast Rules
All UI surfaces, text, borders, icons, and focus outlines strictly use the 11 Section 4 solid hex colors. Zero gradients, zero neon, zero glow shadows, zero pastel fills.

Mathematical WCAG 2.1 contrast audit of Section 4 pairs revealed two critical rules enforced in code and verified by automated tests:

1. **Amber (`#B7791F`) is non-text UI only**:
   - `#B7791F` has contrast `3.64:1` on `White (#FFFFFF)`, `3.39:1` on `Cloud (#F5F7FA)`, `4.05:1` with `Ink (#1F2933)`, and `4.23:1` with `Deep Navy (#0B2545)`. None of those pairs meet `4.5:1` for normal text, though all exceed `3.0:1` (WCAG 1.4.11 non-text UI contrast).
   - **Rule**: Caution/Pending chips, alerts, and stage indicators render `White (#FFFFFF)` surface + `Ink (#1F2933)` text (`14.76:1`) + `Amber (#B7791F)` `1px` border and icon (`3.64:1`). Amber is never used as text foreground or behind text.
2. **Verified Green (`#1B7F5C`) cannot sit on Pale Blue (`#E8EEF6`)**:
   - `#1B7F5C` achieves `4.96:1` on `White (#FFFFFF)` and `4.62:1` on `Cloud (#F5F7FA)` (passes `4.5:1`), and `White` text on `#1B7F5C` achieves `4.96:1` (passes `4.5:1`). However, `#1B7F5C` on `Pale Blue (#E8EEF6)` drops to `4.25:1` (fails AA text).
   - **Rule**: Verified Green text/icons are paired exclusively with `White` or `Cloud` (or `White` on `Verified Green` background).

### 3. Max 3 Non-Neutral Colors Per View
- Neutrals: `Cloud (#F5F7FA)`, `White (#FFFFFF)`, `Ink (#1F2933)`, `Slate (#52606D)`, `Mist (#CBD2D9)`.
- Brand / Highlight / Semantic: `Deep Navy (#0B2545)`, `Trust Blue (#1E56A0)`, `Pale Blue (#E8EEF6)`, `Verified Green (#1B7F5C)`, `Amber (#B7791F)`, `Brick Red (#B42318)`.
- Product screens show at most 3 non-neutral colors simultaneously (typically `Deep Navy` + `Trust Blue` + one active semantic state). On `/style-guide`, a "Focused 3-Accent Mode" and "Full Component Matrix" toggle let reviewers verify both the 3-color rule and all component variants on one page.

### 4. Typography, Hero Numbers & Mobile Floor
- **Fonts**: `Inter` (UI & body) and `Source Serif 4` (headlines) loaded via `next/font/google` with reliable local fallbacks (`system-ui`, `Georgia`).
- **Scale**: Strictly `14px`, `16px`, `20px`, `28px`, `40px`.
- **Rule**: Body text is `>= 16px` (`text-16`) across mobile (`360px`) and desktop (`1280px`). `14px` (`text-14`) is reserved strictly for status chips, table/metric metadata, and form helper text. All financial metrics and stage indices enforce `font-variant-numeric: tabular-nums`.

### 5. Shape, Spacing, Motion & Focus States
- **Spacing**: Strict `8px` grid (`8px`, `16px`, `24px`, `32px`, `40px`, `48px`, `64px`).
- **Corner Radius**: `8px` across cards, inputs, buttons, and chips.
- **Elevation, Opacity & Borders**: `1px solid #CBD2D9` (Mist) borders instead of heavy shadows (`box-shadow: none`). Disabled controls (`bg-cloud text-slate border-mist`, `6.02:1` AA) and modal backdrops (solid `bg-deep-navy`) use 100% solid Section 4 colors rather than CSS `opacity` so colors never blend outside Section 4 or drop below WCAG AA contrast.
- **Required Form Indicators**: Required field markers use neutral `Slate (#52606D)` `(required)` text instead of `Brick Red`, reserving `Brick Red` strictly for errors and risk.
- **Tooltips / Disclosures on Touch & Desktop**: `InfoTooltip` supports click/tap toggle (for 360px touch devices), hover/focus, `Escape` dismissal, and `16px` readable copy clamped within mobile viewports.
- **Focus Ring**: `2px solid #1E56A0` (Trust Blue) outline with `2px` offset (`outline-offset: 2px`) on every interactive element, never glow/blur shadows.
- **Motion**: State-change transitions only (`150ms–250ms ease-out`, defaulting to `200ms`), disabled automatically under `@media (prefers-reduced-motion: reduce)`.

### 6. Authentication & Mandatory 2FA Gate
- **Decision**: Implemented a provider-agnostic auth boundary (`src/lib/auth/`) using `jose` (HS256 signed HTTP-only cookies), `node:crypto` (`scryptSync` + `timingSafeEqual`) for local credential verification, and `otpauth` (RFC 6238 TOTP) for 2FA.
- **Why**: Avoids writing custom cryptographic primitives while functioning without external Clerk/Auth0 keys in local development and CI. Ready to swap to Clerk/Auth0/OIDC via `AUTH_PROVIDER` in production.
- **Trust Invariant**: `canEnterDealRoom(session)` strictly denies access unless `session.twoFactorVerifiedAt` is a valid timestamp and the user holds an authorized role (`BUYER`, `SELLER`, `ADMIN`, `REVIEWER`). Login attempts are rate-limited in memory/Redis.

### 7. Database (PostgreSQL + Prisma) & Queues (Redis)
- **Decision**: `prisma/schema.prisma` targets PostgreSQL (`provider = "postgresql"`) and models all 19 core Section 8 entities (`User`, `Role`, `BuyerProfile`, `SellerProfile`, `Thesis`, `Business`, `BusinessMetric`, `Verification`, `Match`, `DealRoom`, `DealStage`, `Message`, `Document`, `DocumentView`, `Offer`, `ChecklistItem`, `EscrowTransaction`, `Notification`, `AuditLog`).
- **Local Development**: `docker-compose.yml` provides `postgres:16-alpine` and `redis:7-alpine`. When `DATABASE_URL` is absent in local Phase 0 smoke mode, auth falls back to an explicit, clearly labeled local development store (`AUTH_PROVIDER=local-dev`) rather than silently pretending to persist to Postgres.

### 8. Configurable Currency (Default `INR`)
- **Decision**: `src/lib/format/currency.ts` formats monetary figures using `Intl.NumberFormat` defaulting to `INR` (`en-IN`), with optional Indian compact shorthand (`L`, `Cr`) paired with full exact values and configurable support for `USD`, `EUR`, and `GBP`.

### 9. Verification & Testing in CI
- **CI**: `.github/workflows/ci.yml` runs `prisma validate`, `eslint`, `tsc --noEmit`, `vitest run`, `next build`, and Playwright responsive/accessibility verification.
- **Browser Testing**: Playwright targets installed system Chrome/Edge cleanly at `360x800` (mobile) and `1280x800` (desktop) to verify layout, zero horizontal overflow, visible keyboard focus, zero CSS gradients, and WCAG contrast.

## Phase 1: Listings and Vitals

### 10. Listing Schema Extensions & Q&A Persistence
- **Decision**: Extended `Business` in `prisma/schema.prisma` with `teaserSummary`, `founderStory`, `founderMediaType`, `techStack`, `financialSeriesJson`, `valuationLow`, `valuationHigh`, `valuationBasis`, `submittedAt`, `reviewedAt`, `reviewedById`, and `reviewerNote`, and added a dedicated `ListingQuestion` model for public buyer Q&A threads.
- **Why**: Supports all Section 5 & Section 6 Listing page elements (including financial charts, tech & assets, and Q&A) with normalized persistence and auditability.

### 11. Conservative Guided Valuation & Zero-Hype Framing
- **Decision**: Implemented `calculateGuidedValuation()` in `src/lib/domain/valuation.ts` using conservative sector profit multiples (`1.5x–4.0x` depending on sector, adjusted for weekly owner hours and annual growth rate, with a `0.8x–1.4x` pre-profit revenue fallback). Every output includes an explicit disclaimer that it is an illustrative estimate from seller-reported inputs, never a guaranteed exit price.
- **Why**: Aligns with Section 2 ("Never fake trust", "Never use urgency tricks or hype") and Section 3 ("guided valuation, auto-built listing").

### 12. Server-Side Redaction & Confidential Leak Guard
- **Decision**: `sanitizeListingForViewer()` in `src/lib/domain/listings.ts` strips `redactedName`, `redactedDomain`, `redactedCustomers`, and internal `reviewerNote`/`auditLogs` on the server unless the viewer is the owning Seller, an Admin/Reviewer, or a Buyer with a completed NDA. `detectConfidentialLeak()` blocks submission for Admin review if `redactedName` or `redactedDomain` appears inside public teaser fields.
- **Why**: Enforces Section 6 ("Sensitive details (name, domain, customer names) are redacted until NDA is signed") at the data-serialization boundary rather than relying on client-only CSS hiding.

### 13. Strict Separation of Verified vs Seller-Reported Vitals
- **Decision**: Seller-created listings in Phase 1 create `BusinessMetric` rows strictly with `source = SELLER_REPORTED` and `verificationId = null`; API endpoints ignore any client-supplied verification fields. The Listing detail page separates **Verified connected metrics** (`Verified Green`, active `Verification` record + source + `Last verified` timestamp) from **Seller-reported metrics (unverified)** (neutral `Cloud`/`Mist` panel + `Seller-reported` chip). Seeded sample listings (`isSampleData: true`) supply real `Verification` records (`Stripe`, `GA4`, `Razorpay`) to demonstrate the distinction cleanly until Phase 3 live connectors launch.
- **Why**: Satisfies Section 2, Section 6, and Phase 1 acceptance criteria without faking trust.

### 14. Status-Tabbed Seller & Admin Views for the 3-Color Rule
- **Decision**: `/seller` and `/admin/review` organize listings into Radix Tabs by status (`Drafts & pending` / `Pending review`, `Approved`, `Flagged & rejected`). Admin review decisions (`APPROVE`, `FLAG`, `REJECT`) require a minimum 5-character reviewer note and append an `AuditLog` entry.
- **Why**: Prevents mixing `Amber`, `Verified Green`, and `Brick Red` chips on a single screen, maintaining Section 4's limit of `<= 3` non-neutral colors visible per view alongside `Deep Navy` and `Trust Blue`.

### 15. Local Founder Voice Note Media Endpoint
- **Decision**: Added `/api/media/sample-founder-note` returning a deterministic PCM WAV audio stream for sample listings and restricted `founderMediaUrl` to `https://` or `/api/media/` paths via `sanitizeFounderMediaUrl()`.
- **Why**: Avoids broken external media URLs, console 404 errors, and `javascript:`/`http:` URL risks while keeping the Section 6 `<audio controls>` founder voice note functional offline and in CI.

## Next: Phase 2 Plan (Buyer Thesis and Matching)
1. **Buyer Thesis Builder (`/thesis/new` & Home prompt wiring)**: Guided structured inputs (sector, revenue range, net profit floor, max owner hours/week, geography, target price range, currency) plus free-text narrative persisted to `Thesis`.
2. **Transparent Match Scoring Engine**: Weighted hard-criteria scoring (`price`, `revenue`, `profit`, `ownerHours`, `sector`, `geography`) combined with keyword/semantic free-text scoring, explicitly outputting both `Why this matches` and `What doesn't fit` mismatches for every ranked `Match` record.
3. **Saved-Thesis Feed & Matches View (`/matches`)**: Replace the Phase 0/1 empty thesis preview on Home with live saved theses, ranked matches with fit scores, and one-line explanations.
4. **Side-by-Side Compare View (`/compare`)**: Compare up to 3 businesses cleanly across price, verified vs seller-reported vitals, owner hours, risks, and match mismatches at both 360px and 1280px.
5. **Thesis Alerts (`Notification`)**: Generate `Notification` alerts when newly approved listings match an existing saved thesis with `alertsEnabled: true`.
